# 手動測試清單

UI 與連線以手動測試為主（SDD §8）。每個里程碑完成時，依本文件逐項執行並勾選。
core 與 ai 的邏輯由 `ctest` 涵蓋，這裡只測畫面與操作。

**通用前置條件**：
```bash
cmake --build build -j && ./build/gomoku
```

---

## 里程碑 2：本機雙人對局

### M2-1 啟動畫面
| 步驟 | 預期結果 |
|---|---|
| 啟動程式 | 標題「Gomoku」；選單列在視窗內（標題列正下方），有「遊戲(G)」 |
| 看棋盤 | 15×15 格線、木頭色底、5 個星位（(3,3)、(3,11)、(7,7)、(11,3)、(11,11)），沒有棋子 |
| 看狀態列 | 「輪到黑方」 |

### M2-2 落子與輪替
| 步驟 | 預期結果 |
|---|---|
| 點天元 | 出現黑子，上面有紅點；狀態列「輪到白方」 |
| 點旁邊的交叉點 | 出現白子，紅點移到白子上；狀態列「輪到黑方」 |
| 點四個角落的交叉點各一次 | 棋子完整出現在角落，沒有被切掉 |

### M2-3 非法點擊（應完全沒有反應）
| 步驟 | 預期結果 |
|---|---|
| 點已有棋子的位置 | 棋盤與狀態列不變 |
| 點兩條格線的正中間 | 不落子 |
| 點棋盤外的邊距或左右空白處 | 不落子 |
| 按右鍵、中鍵 | 不落子 |

### M2-4 視窗縮放
| 步驟 | 預期結果 |
|---|---|
| 把視窗拉成很寬的長方形 | 棋盤維持正方形並水平置中，多出的部分為木頭色 |
| 把視窗拉成很高的長方形 | 棋盤維持正方形並垂直置中 |
| 縮放後點幾個交叉點 | 落點與點擊位置一致 |
| 縮到最小 | 視窗無法小於棋盤最小尺寸（240×240），畫面不破圖 |

### M2-5 勝負判定
每項各下一局，用「再來一局」接續下一項。

| 步驟 | 預期結果 |
|---|---|
| 黑方橫向連五 | 對話框「對局結束」，內容「黑方勝（連五）」 |
| 白方直向連五 | 「白方勝（連五）」 |
| 任一方左上到右下斜向連五 | 對應的一方勝（連五） |
| 任一方右上到左下斜向連五 | 對應的一方勝（連五） |
| 同一方在一條線上先下第 1、2、3、4、6 格，最後補第 5 格成六連 | 判勝（六連也算） |
| 下到四連後被擋住 | 不判勝，遊戲繼續 |

和局（棋盤下滿）需要 225 手，不列入手動測試，由 core 測試 `GameState` 盤滿和局涵蓋。

### M2-6 結束對話框
| 步驟 | 預期結果 |
|---|---|
| 分出勝負時看對話框 | 有「再來一局」與「關閉」兩個按鈕，「再來一局」為預設 |
| 直接按 Enter | 等同「再來一局」：棋盤清空，狀態列「輪到黑方」 |
| 再分出勝負後按「關閉」 | 棋盤保留終局，狀態列顯示結果（如「黑方勝（連五）」） |
| 「關閉」後點棋盤 | 不落子 |

### M2-7 選單與快捷鍵
| 步驟 | 預期結果 |
|---|---|
| 對局中途按「遊戲 → 新對局」 | 棋盤立即清空（不會詢問），狀態列「輪到黑方」 |
| 對局中途按 Ctrl+N | 同上 |
| 對局結束後按 Ctrl+N | 同上，棋盤恢復可以點擊 |
| 按 Alt+G | 開啟「遊戲」選單 |
| 按「遊戲 → 離開」 | 程式結束 |
| 重開程式後按 Ctrl+Q | 程式結束 |

## 里程碑 3：存讀檔、棋譜、回放

存檔格式與讀檔驗證由 `ctest`（GameRecord、SaveFormat、ReplayCursor）涵蓋，這裡只測操作流程。
以下「錯誤檔案」可用文字編輯器修改一份正常存檔來製作。

### M3-1 選單
| 步驟 | 預期結果 |
|---|---|
| 開啟「遊戲」選單 | 依序為：新對局、存檔…、讀檔…、匯出棋譜…、回放棋譜…、離開 |
| 對局進行中看「匯出棋譜」 | 灰色，不能按 |
| 分出勝負後看「匯出棋譜」 | 可以按 |

### M3-2 存檔
| 步驟 | 預期結果 |
|---|---|
| 下幾手後按 Ctrl+S | 出現存檔對話框，預設在「文件」資料夾，檔名如 `gomoku-20261005-205124.gomoku.json` |
| 檔名改成 `test`，存檔 | 實際存成 `test.gomoku.json`；狀態列顯示「已儲存到 test.gomoku.json」約 3 秒 |
| 用文字編輯器開啟該檔 | 內容符合 SDD §6.1：`matchType` 為 `local`、`timeControl.mode` 為 `none`、`moves` 與棋盤一致、`result` 為 `null` |
| 再存一次，檔名同樣輸入 `test` | 詢問「test.gomoku.json 已存在，要覆蓋嗎？」；選否則不寫入 |
| 存檔對話框按取消 | 沒有任何變化 |
| 再次存檔 | 對話框開在上次使用的資料夾 |

### M3-3 讀檔
| 步驟 | 預期結果 |
|---|---|
| 開新局後按 Ctrl+O，選 M3-2 的檔案 | 棋盤回到存檔時的局面，紅點在最後一手，狀態列輪到正確的一方；狀態列顯示「已讀取 …」約 3 秒 |
| 讀檔後繼續下到分出勝負 | 正常判勝 |
| 讀入一份已結束的棋譜 | 狀態列顯示結果，棋盤不能落子，「匯出棋譜」可以按 |
| 讀檔對話框按取消 | 目前對局不變 |

### M3-4 讀檔錯誤（每項讀檔失敗後，目前對局都應保持不變）
| 錯誤檔案 | 預期訊息 |
|---|---|
| 內容不是 JSON（例如只寫 `hello`） | 「不是有效的 JSON：…」 |
| 刪掉 `moves` 欄位 | 「缺少欄位 moves」 |
| 把某一手的 `r` 改成 `"7"` | 「欄位 moves[n].r 的型別錯誤，應為整數」 |
| 把 `version` 改成 `2` | 「不支援的存檔版本 2（目前支援 1）」 |
| 讓第 2 手和第 1 手位置相同 | 「第 2 手不合法：(r,c) 已有棋子」 |
| 已連五的棋譜把 `result` 改成 `null` | 「棋譜記錄對局尚未結束，但重播後已分出勝負」 |
| SDD §6.1 的範例（人對電腦、限時） | 「目前只支援讀取本機雙人、不限時的對局」 |

### M3-5 匯出棋譜
| 步驟 | 預期結果 |
|---|---|
| 分出勝負後按「遊戲 → 匯出棋譜」 | 出現對話框，標題為「匯出棋譜」；存檔後狀態列顯示「已儲存到 …」 |
| 開啟匯出的檔案 | `result` 有 `winner` 與 `reason`，例如 `"black"`、`"five_in_row"` |

### M3-6 回放
| 步驟 | 預期結果 |
|---|---|
| 「遊戲 → 回放棋譜」，選一份已結束的棋譜 | 棋盤清空，下方出現按鈕列；狀態列「回放：第 0 / N 手」；開頭、上一步為灰色 |
| 按「下一步」數次 | 每次多一顆子，紅點在最新一手，手數 +1 |
| 按「上一步」 | 最新一手消失，紅點移到前一手 |
| 按「結尾」 | 顯示全部棋子；狀態列「回放：第 N / N 手　黑方勝（連五）」（依棋譜）；播放、下一步、結尾為灰色 |
| 按「開頭」 | 棋盤清空，回到第 0 手 |
| 按「▶ 播放」 | 按鈕變為「⏸ 暫停」，每秒前進一手，到最後一手自動停止並變回「▶ 播放」 |
| 播放中按「⏸ 暫停」 | 停在目前這一手 |
| 播放中按「下一步」 | 前進一手並停止自動播放 |
| 回放中點棋盤 | 不落子 |
| 回放中看「存檔」「匯出棋譜」 | 皆為灰色；Ctrl+S 沒有反應 |
| 回放一份未結束的存檔 | 可以回放；最後一手時狀態列只顯示手數 |
| 回放人對電腦或限時的棋譜（如 SDD §6.1 範例） | 可以回放 |
| 回放有錯誤的檔案（M3-4 任一項） | 「無法回放」並顯示原因，目前畫面不變 |
| 按「結束回放」 | 按鈕列消失，回到空白新局，狀態列「輪到黑方」 |
| 回放中按 Ctrl+N | 離開回放，空白新局 |
| 回放中按 Ctrl+O 讀入存檔 | 離開回放，顯示讀入的對局 |
